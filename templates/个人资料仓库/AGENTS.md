# AGENTS.md

本文件是家庭个人资料仓库的 AI 维护入口。开始处理个人信息前，先阅读本文件、仓库 `README.md` 和任务对应的记录页面。

最近更新：请在采用模板时填写日期。

## 仓库定位

本仓库只保存家庭个性化孕期进度，用于维护当前节点、具体预约、症状、医生确认信息、办事状态和家庭调研记录。通用医学知识、公共政策和可复用清单应维护在通用知识库，不在这里重复扩展。

通用知识库的名称与位置由当前工作区或用户配置提供，不写死在本模板中。需要维护通用规则时，先定位对应知识库并阅读其 `AGENTS.md`；未提供入口时先向用户确认。

本仓库即使使用私有远端，也不保存账号密码、短信验证码、完整证件号码、银行卡号、报告照片、二维码、支付凭证或不必要的详细住址。

## 记录入口

采用模板时，在仓库 `README.md` 中列出实际记录页面及用途，例如：

- 当前记录页：孕周、预约、症状、检查摘要、办理状态和下一步。
- 专题调研页：候选机构、报价、服务答复和家庭决定。

记录文件可以按家庭需要命名；不要依赖通用知识库中的固定路径。

## 更新触发

用户提供或确认以下新信息时，Agent 应识别为记录更新并直接维护，不等待用户再次要求“写入记录”：

- 医生确认的孕周、预产期、检查结论摘要和下一次安排。
- 新增、变更或取消的预约时间、院区、科室及准备要求。
- 新出现、缓解或变化的症状，以及用户明确转述的医生处理意见。
- 医保、生育登记、社区健康管理、单位手续等个性化办理状态。
- 已完成事项、下一步待办和需要在指定日期提醒的问题。
- 家庭调研中的新增候选、报价、服务答复、淘汰原因和最终选择。

没有用户反馈或医生确认时，不自行推断事项已完成，不把通用知识写成个人诊断或医嘱。

## 记录原则

- 区分“用户观察”“医生确认”“计划待办”和“已完成”，不混写为确定医学结论。
- 动态状态优先替换过期内容并保留必要日期，不无限追加重复流水。
- 医生原话无法准确复述时写成摘要，并注明由用户转述。
- 原始检查报告和证件材料保存在家庭安全位置，本仓库只记录必要摘要和文件所在位置。
- 个人记录变化不反向复制到通用知识库；只有通用规则确实变化时，才单独维护通用知识库。

## Git 约定

- 本仓库应与通用知识库使用独立 Git 历史和访问受控的远端。
- 开始前运行 `git status --short --branch` 并查看最近提交，保护已有改动。
- 内容有更新时，按可独立理解、验证和回滚的最小事项提交；不同事件或主题分别提交。
- 提交前检查差异，确认没有混入无关修改、秘密信息或不必要的敏感原件。
- 默认在完成修改、验证和提交后询问用户是否推送。若家庭明确采用自动推送，应在本节写明，并在失败时保留本地提交、说明原因和未推送提交数。
- 不强制推送，不使用破坏性 Git 命令，除非用户明确授权。

## 完成前检查

```bash
git diff --check
git status --short --branch
```

人工确认当前节点、日期、已完成状态和下一步没有互相矛盾，并确保没有把待确认事项写成已经完成。

## 采用模板时必须调整

- 在 `README.md` 中登记实际记录入口。
- 明确通用知识库的发现方式，但不要把私人仓库位置写回通用知识库。
- 明确采用“询问后推送”还是“验证后自动推送”。
- 将“最近更新”替换为实际日期。
