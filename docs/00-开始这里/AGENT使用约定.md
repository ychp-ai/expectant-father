# AGENT 使用约定

本页约定使用 AI Agent 查询和维护本知识库时的基本做法。目标是让 Agent 给出可执行、可追溯且不泄露家庭隐私的结果。

## 开始任务前

Agent 开始处理任务前应完成以下检查：

1. 阅读仓库根目录的 [`AGENTS.md`](../../AGENTS.md)、[`README.md`](../../README.md) 和任务对应的专题文档。
2. 运行 `git status --short --branch`，确认已有改动，避免覆盖与本次任务无关的内容。
3. 查看最近提交，确认相同事项是否已经完成。
4. 先说明准备处理的范围；信息足够时直接推进，只有关键条件缺失且无法安全判断时再询问。

## 信息放在哪里

| 信息类型 | 保存位置 | 基本要求 |
|---|---|---|
| 通用孕期知识、杭州公共规则、浙大妇院通用场景 | `docs/`、`references/` | 可以提交到 Git；动态信息需附官方来源和最近复核日期 |
| 当前孕周、具体预约、症状、办理进度、医生沟通问题 | 用户指定的私人资料仓库或受控私人记录工具 | 仅在用户明确提供或确认后更新；不进入当前公共仓库 |
| 姓名、证件号码、电话、详细住址、病历号、报告照片、二维码、支付凭证 | 不写入知识库 | 如任务确实需要，应提醒用户改用安全的私人记录方式 |

Agent 不得根据行动计划自行推断个人事项已经完成，也不得把私有记录中的个人信息复制到通用文档。

使用 Git 保存个人资料时，应建立独立仓库和独立历史，仓库名称、位置和远端由使用者自行配置。处理个人记录前，先根据当前工作区或用户提供的上下文定位私人资料并阅读其 `AGENTS.md`；未提供入口时不得猜测。识别到已确认的个人记录变化后，按该仓库自己的提交和推送约定执行。新建仓库可从[个人资料仓库模板](../../templates/个人资料仓库/README.md)开始。

## 回答和修改原则

- 使用简体中文，先给结论或下一步行动，再补充必要背景。
- 优先引用已有知识库页面；同一规则只保留一个详细说明入口，其他页面使用链接，避免重复内容逐渐不一致。
- 区分“必须办理”“必须完成”“符合条件时办理”和“建议准备”，不把建议写成强制要求。
- 修改范围应聚焦当前任务，保留用户已有且与任务无关的改动。
- 新增页面后补充所属模块的导航入口，并检查内部链接、标题层级、清单和表格。

## 医疗和动态信息边界

- 不进行个人诊断，不解释检查结果，不调整药物，也不替用户决定治疗或产前筛查方案。
- 涉及医疗、政策、医保、劳动权益和医院流程时，优先核对政府、卫生健康部门、医保部门或医院的官方来源。
- 动态内容应写明适用地区、适用条件、官方来源和最近复核日期。
- 按[参考资料中的复核时效规则](../../references/README.md#复核时效规则)检查过期来源；实际办理、预约或就诊前仍要打开责任机构当次页面确认。
- 无法由官方来源确认的材料、时间或流程，应明确写成“办理前确认”，不得推测为全杭州或所有院区统一要求。
- 每次就诊或预约前，提醒重新确认院区、科室、时间和报到地点。

## 完成任务前

Agent 应至少完成以下检查：

```bash
python3 scripts/check_knowledge_base.py
git diff --check
git status --short --branch
```

并人工确认：

- 新增或修改的内部链接可以打开。
- 医疗、政策、医保、劳动权益和医院流程内容有来源编号及最近复核日期。
- 没有写入或准备提交个人隐私、详细预约、检查报告或支付凭证。
- 没有把不同事项混入同一次修改或提交。

使用过程中产生知识库更新时，应按可独立理解、验证和回滚的最小事项提交；不同知识事项分别提交，不把无关修改混入同一提交。

完成本次任务和最终验证后，Agent 应汇总本次提交并向用户确认是否推送。得到明确确认前不推送远端。不使用破坏性 Git 命令，不强制推送，除非用户明确授权。

## 约定的维护

- 本页维护日常使用 Agent 时的稳定基础约定。
- [`AGENTS.md`](../../AGENTS.md) 维护项目定位、当前状态、后续方向和 AI 交接入口。
- 两处共同涉及的隐私边界、验证方式或 Git 规则发生变化时，应在同一事项中同步更新。
