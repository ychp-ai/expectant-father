# 通用知识与浙江杭州地方适配拆分设计

## 背景

当前知识库同时承载全国通用的孕期知识、浙江省级政策、杭州办事规则和浙江大学医学院附属妇产科医院流程。地方内容既有独立页面，也散落在行动计划、产检指南、爸爸指南、执行清单和项目入口中，导致通用知识与地方适配相互混杂。

本次调整在同一仓库内建立独立的地方适配层，使通用知识可以脱离杭州和特定医院单独使用，同时继续保留维护者家庭需要的浙江杭州及浙大妇院资料。

## 目标

- 将浙江省级政策、杭州办事规则和浙大妇院流程从通用知识正文中抽离。
- 使 `docs/00-开始这里` 至 `docs/08-记录模板` 成为地区中立的通用知识区。
- 在 `docs/09-地区与医院适配/浙江杭州/` 集中维护全部浙江、杭州和浙大妇院强绑定内容。
- 保留清晰的阅读衔接：用户先阅读通用行动框架，需要时再进入地方适配入口。
- 通过自动检查阻止地方内容重新混入通用正文。

## 非目标

- 不把地方内容迁移到其他仓库。
- 不删除现有浙江杭州或浙大妇院知识。
- 不改变当前孕期为核心、出生后只保留必要登记的范围。
- 不在本次结构调整中新增未经确认的政策、医院流程或个人办理信息。
- 不把个人孕周、预约、症状、报告或办理状态写入公共知识库。

## 信息架构

新增目录结构如下：

```text
docs/09-地区与医院适配/
├── README.md
└── 浙江杭州/
    ├── README.md
    ├── 01-浙江省级政策/
    ├── 02-杭州办事/
    ├── 03-浙大妇院/
    └── 04-地方执行清单/
```

各层职责如下：

| 区域 | 职责 | 允许包含的内容 |
|---|---|---|
| `docs/00`～`docs/08` | 通用知识 | 全国通行的医学知识、行动框架、准备方法、记录模板和办事方法 |
| `01-浙江省级政策` | 省级适配 | 浙江生育保险、假期权益、津贴发放及其他省级现行规则 |
| `02-杭州办事` | 城市适配 | 杭州社区、医保、登记、补助、公积金和出生联办事项 |
| `03-浙大妇院` | 医院适配 | 医院系统产检、建档衔接、预约、院区、急诊和分娩前确认事项 |
| `04-地方执行清单` | 综合执行 | 将省、市、医院事项按孕期阶段汇总为地方清单 |

地方模块正式使用“浙江大学医学院附属妇产科医院”或“浙大妇院”。“省妇保”只在地方模块入口说明为常用称呼，不作为正式文件名或政策主体名称。

## 内容归属规则

### 整页地方内容

现有以杭州政策、杭州办事或浙大妇院流程为主体的页面整体迁入地方模块，包括杭州建小卡、生育登记、医保与生育保险、生育权益、生育补助、公积金、出生一件事和杭州孕期必办事项等页面。

迁移时保留原有来源编号、复核日期、适用条件和风险提醒，只调整目录、导航和必要的上下文表述。

### 混合页面

以下类型的页面需要拆分，而不是整体搬走：

- 建档准备、小卡与医院系统产检等同时讲通用概念和杭州流程的页面。
- 单位手续、单位费用、分娩前行政准备等同时包含全国原则和浙江杭州待遇的页面。
- 行动计划、时间线、三方行动表、产检指南、爸爸指南和通用执行清单中的地方任务。
- 中期筛查、胎心监护、首次产检和分娩前筛查中的社区反馈或浙大妇院要求。

拆分后，通用页面只保留地区中立的概念、判断方法、准备清单和行动顺序；被移除的地方段落进入地方模块对应专题或地方执行清单。

### 通用页面的地方入口

确实需要地方补充的通用页面可在末尾增加统一的地方适配区块：

```markdown
## 地方适配

- [浙江杭州与浙大妇院适配](../09-地区与医院适配/浙江杭州/README.md)
```

相对路径按页面所在目录调整。该区块只链接地方总入口，不直接列出多个杭州政策页或医院流程页。除这个标准区块外，通用正文不得出现浙江、杭州、浙大妇院、省妇保、浙里办、浙里医保、善育在杭等地方内容。

## 导航与依赖关系

- 根 `README.md`、`docs/README.md` 和开始页将“通用知识”和“地方适配”作为并列入口展示。
- 通用阅读顺序只串联 `docs/00`～`docs/08`，不把杭州事项插入通用阶段任务。
- 地方模块可以链接通用医学、行动计划、物资和记录页面，以复用稳定知识。
- 通用专题只能通过标准地方适配区块链接地方总入口，避免对某个地方页面形成深层依赖。
- 地方总入口负责把通用阶段映射到浙江省级政策、杭州办事和浙大妇院流程。

## 来源目录拆分

`references/README.md` 保留来源使用规则、复核时效、编号规范和两个来源目录的导航。具体来源拆分为：

- `references/通用来源.md`：`CN-*`、`WHO-*`、`NHS-*`、`ACOG-*`、`RCOG-*`、`MAYO-*`、`FDA-*`、`COCHRANE-*` 等通用来源。
- `references/浙江杭州与浙大妇院来源.md`：`ZJ-*`、`HZ-*`、`WHZJU-*` 地方来源。

通用知识区不得引用地方来源编号。地方模块可以同时引用通用来源和地方来源。

## 自动检查

调整 `scripts/check_knowledge_base.py`：

1. 从多个来源文件汇总有效来源和停用来源，继续检查未定义来源、未使用来源、必要字段和复核时效。
2. 将 `docs/00-开始这里` 至 `docs/08-记录模板` 定义为通用知识区。
3. 检查通用正文是否出现地方关键词或 `ZJ-*`、`HZ-*`、`WHZJU-*` 来源编号。
4. 检查地方关键词时忽略标准“地方适配”区块，使通用页面可以保留唯一的地方总入口。
5. 继续执行一级标题、内部链接、孤立页面、复核日期、医学窗口和敏感数字检查。

根项目说明、维护约定、总导航和地方适配目录属于信息架构说明，不作为通用医学正文处理；这些页面可以说明两层结构，但不得重新承载具体地方办理规则。

## 迁移顺序

1. 建立地方适配目录、入口和来源目录。
2. 迁移整页地方内容并修复其内部链接。
3. 拆分办事指南中的通用与地方内容。
4. 清理行动计划、产检指南、爸爸指南、执行清单和开始页中的地方段落。
5. 更新根导航、模块导航、项目定位、维护约定和知识库状态快照。
6. 更新检查脚本并执行全库验证。

迁移过程中优先保持原有知识和来源关系，不在同一次结构调整中扩充政策结论。若发现事实冲突或来源过期，应作为独立知识事项处理和提交。

## 提交策略

按可独立验证和回滚的最小事项提交：

1. 建立地方适配结构并迁移整页地方内容。
2. 拆分混合页面并清理通用区。
3. 拆分来源目录并增加自动隔离检查。
4. 更新入口、项目说明、维护约定和状态快照。

每个提交前运行与改动范围相称的检查；全部完成后运行完整验证。未经用户明确确认不推送远端。

## 验收标准

- `docs/00`～`docs/08` 的通用正文不包含浙江、杭州或浙大妇院具体规则。
- 通用页面只通过统一的地方适配区块链接地方总入口。
- 省级政策、杭州办事、浙大妇院流程和地方执行清单均可从地方总入口到达。
- 所有原有有效知识均有明确归属，没有因迁移丢失来源、复核日期或适用条件。
- 通用来源与地方来源分开维护，正文引用均可解析。
- `python3 scripts/check_knowledge_base.py`、`git diff --check` 均通过。
- 人工核对内部导航清晰，没有个人身份、预约、检查报告、联系方式、住址或支付凭证进入公共仓库。
